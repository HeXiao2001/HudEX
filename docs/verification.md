# HudEX v1 — 验证记录

所有测试都在当前机器上实测：macOS 26.6.2 (25G113 / BuildVersion 25G83)、
Xcode 26.6、Apple Swift 6.3.3、MacBook 内建 Retina 显示器 1470×956 pt @2x、
Dock 在左侧、tilesize 34（保留带 54 pt）、有菜单栏（33 pt）。

## 1. 构建与单元测试

```
swift build --product HudEX          # 成功，无 error / warning（HudEXApp + HudEXCore）
swift test                           # 71 项测试通过
./script/build_and_run.sh            # 组装 dist/HudEX.app + ad-hoc 签名 + 启动
```

测试分布：解析 11、Markdown 渲染与文件 10（含原子替换、编码回退、空文件）、
布局引擎 17、Dock 几何估算 10、颜色与短名 15、模板 1。

## 2. Dock 三个方向（窗口列表实测）

用 `CGWindowListCopyWindowInfo` 读取 HudEX 自己窗口的真实坐标（AppKit 坐标）：

| Dock 位置 | 标签面板实测矩形 | 说明 |
|---|---|---|
| 左侧 | `x 0, y 8, w 54, h 85` | 贴左边缘，宽 54 = Dock 厚度，在 Dock 下方 |
| 下方 | `x 8, y 0, w 85, h 54` | 贴下边缘，高 54 = Dock 厚度，从左侧向右排 |
| 右侧 | `x 1416, y 8, w 54, h 85` | 贴右边缘（1470-54） |
| 再次左侧 | `x 0, y 8, w 54, h 85` | 换回后立即恢复 |

切换 Dock 方向时没有重启 HudEX：位置变化由系统通知驱动，实测切换后 1–6 秒内更新。

## 5. 空闲性能（Release 级行为，5 分钟）

测量方式：外部进程用 `proc_pid_rusage(RUSAGE_INFO_V4)` 每 30 秒采样一次。

两组独立测量：

**A. 全新启动、只显示标签（90 秒）**

| 指标 | 结果 |
|---|---|
| 空闲 CPU | 采样窗口内累计 CPU 时间 **0.000 s**，平均 **0.0001–0.0002%** |
| 常驻内存 | **14.1 MB** 稳定（峰值 14.1 MB） |
| 唤醒 | 每 30 秒 5 / 7 / 10 次 → **≈0.1–0.3 次/秒** |

**B. 打开过设置/完整窗口之后（5 分钟）**

| 指标 | 结果 |
|---|---|
| 空闲 CPU | 300 秒累计 **0.000 s**，平均 **0.007%** |
| 常驻内存 | 稳定 **67.3 MB**（不再增长） |
| 网络 | **0**：二进制不链接任何网络 API（`nm -u` 中 URLSession/CFNetwork/socket 符号数 = 0），进程无打开的 socket |
| 磁盘 | 空闲时不读写：没有轮询定时器，文件只在 FSEvents 事件后且签名变化时读取 |
| 唤醒 | 启动初始化后 **≈0.5 次/秒** |

内存差异说明：67 MB 是访问过设置窗口（一个较大的 SwiftUI 表单）后的稳态；
刚启动、只显示标签时只有 14 MB。这是 AppKit + 每个窗口一个 `NSHostingView`
的 SwiftUI 运行时成本。如需进一步压低，可以把标签面板改成 CoreGraphics 自绘
（代价是失去 SwiftUI 布局），当前数值已在目标范围内。

## 6. 仍未覆盖 / 已知限制

* 全屏 App 与多 Space：使用 `.canJoinAllSpaces + .canJoinAllApplications +
  .fullScreenAuxiliary + .stationary`，在普通窗口与全屏 Space 下可见；
  没有逐 Space 自动化验证（需要人工切换）。
* 多显示器：只在 Dock 所在的那块屏幕显示，架构上不阻止扩展。
* Dock 长度仍为估算（macOS 26 的 Dock 窗口覆盖全屏，公开 API 无法量长度）。
